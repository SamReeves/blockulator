# Benchmarks

All three tables are regenerated by make targets and checked in CI, so the
committed copies match the code at that commit.

- [`ladder.md`](ladder.md) / [`ladder.json`](ladder.json): **terminal precision.**
  Eight real calculations expressed as N identical steps (daily compounding,
  a square-root bonding curve, exp/ln round trips, an amortising loan, a
  running geometric mean, Black-Scholes d1 along a price path, a cumulative
  product of basis-point factors, and compounding via one real-exponent pow),
  run through FP127 (deployed object and inline library), ABDKMath64x64,
  Solady and PRBMath SD59x18 for N = 1 to 10,000, against the same loop in
  exact arithmetic (mpmath, 200 digits). Each cell gives correct significant
  digits and gas per step. Produced by `make ladder` from
  `test/ladder/Ladder.t.sol`, which calls the same `LadderRunner` contract
  that is deployed on Sepolia, via `scripts/ladder/ladder.py`. Scenario
  parameters and rationale: `scripts/ladder/scenarios.json`.
- [`gas.md`](gas.md) / [`gas.json`](gas.json): gas for every FP127 op across
  an input ladder, for the Huff baseline, the Yul object, `FP127Caller`,
  `FP127Lib` and the three competitor libraries. `make bench`.
- [`../fp127/precision.md`](../fp127/precision.md) / [`../fp127/precision.json`](../fp127/precision.json):
  correct bits of every op against mpmath over the committed vectors.
  `make test` then `make precision-report`.

Library versions: Solady v0.1.26, PRBMath v4.2.0, ABDKMath64x64 v3.2 (the
`versions` block in each JSON records the exact tags and the FP127 commit).
To rerun after a bump, update the submodule, then `make bench ladder`.

## Reading the ladder

"Terminal precision" is the precision a calculation ends with after all its
steps, as opposed to the headline precision of one op. A WAD library keeps
about 60 fractional bits, 18 decimal digits; ABDK 64 bits. FP127 keeps 128.
The ladder shows the digits that survive N steps. Where a library reverts
at some N, the cell says so with the revert selector; that is a result,
not a gap.

The Huff-era fuzz sweep (`precision_distribution.json`, `fuzz_data.txt`
and the scatter plots) is gone; its single-op view is superseded by the
per-op precision table and the ladder.
